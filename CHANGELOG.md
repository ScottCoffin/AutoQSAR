# Changelog

All notable changes to QSARena. Entries are grouped by the work-order item they implement
(`submission/QSARena_IDE_Agent_Work_Order_Manuscript_Code.docx`, v4 / build 26037).

## [Unreleased]

### Added — tutorial & usability work order (`docs/AGENT_WORK_ORDER_tutorial.md`)
- **Unified option surface (F1).** `qsarena.config.RunConfig` is the single source of truth for all
  15 decision groups. `qsarena-benchmark --config run.yaml` (precedence: command line > file >
  defaults), `--help` grouped by decision group, `--version`, actionable validation errors with
  "did you mean" hints, and the resolved config + signature in `run_config.json` /
  `run_config.yaml`. Generated `docs/options_reference.md` and `configs/run.example.yaml`
  (`python -m qsarena.config --write-docs`). New options: SMILES/target/ID columns, multi-target,
  task and classification threshold, standardization (salt stripping, charge/tautomer
  normalization, deduplication, strict unparseable mode), feature-family selection, dedup
  thresholds, explicit random-forest selector, model-family switches and per-model disabling, a
  `quick` profile, GA `on` mode with time/config budgets, GPU policy, primary-metric override,
  in-run applicability domain, selection protocol and report switches. Defaults reproduce the
  previous runner behaviour (new options default off). The notebook loads a `run.yaml` into the
  matching widgets (step 0B) and exports its widget choices back to `run.yaml` (step 9E).
- **Single-dataset mode verified end to end (F2)**, including IDs in `predictions.csv`.
- **Batch mode (F3).** `--batch` accepts a manifest CSV with per-dataset overrides, a directory of
  CSVs, a `.txt` list or several paths; each dataset is isolated, a failing dataset is recorded
  (status, error, remedy) and the batch continues (`--no-continue-on-error` to stop); the aggregate
  `dataset_summary.csv` lists every dataset. No dataset-count limit.
- **Resume hardening (F4).** Every metrics row records a `stage_config_signature`; on resume a
  changed setting recomputes only the affected model families (fusion and ensembles follow their
  members), and a completed dataset is re-validated when its config fingerprint changes. `--fresh`
  moves the old output directory aside (never deletes it). All artifacts are written atomically
  (`qsarena.artifacts`), so an interrupted run resumes without rework; covered by kill-and-resume
  tests.
- **Feedback and reporting (F5).** Preflight checks (parse rate, dropped rows, duplicates, task,
  class balance, size guardrails, missing backends/GPU with install remedies), a `--dry-run` plan
  (datasets x models with skip reasons and a cost estimate, `dry_run_plan.{json,md}`), `run.log`,
  `events.jsonl` at `--verbosity quiet|normal|verbose|debug`, in-run actionable warnings, and a
  self-contained `report.html` plus `report.md` (best model by test and by CV, leaderboard/rank
  table, won-by-family / cost-vs-gap / AD-coverage plots, failures with remedies, "what to do
  next", resolved config) with `report_data.json`.
- **Tutorial example data.** `qsarena-examples DIR` writes the synthetic tutorial datasets shipped
  in `qsarena/examples/data` (regenerated by `tests/fixtures/tutorial/make_tutorial_data.py`).
- **Per-run SHA-256 manifest.** Every run writes `artifact_manifest.csv` (path, bytes, SHA-256 of
  every output file) as its last step.
- **Guided tutorial, Additional file 2 (D1).** `docs/tutorial.md`: entry-point guide with flowchart,
  installation, quickstart, a reference for all 15 option groups (tables generated from RunConfig),
  batch mode, resume, reports, applicability domain, reproducibility and troubleshooting. Built into
  `submission/additional_file_2_qsarena_tutorial.pdf` by `submission/build_additional_file_2.py`; the
  manuscript's Availability section and Additional-file list cite it (both formats). Additional
  file 1 is unchanged.
- **Executable-docs guarantee (D2).** `tests/docs/test_tutorial_runs.py` runs every tutorial command
  on the example data, matches every output excerpt, checks every documented flag against `--help`,
  validates every YAML snippet, checks the generated tables and plot assets are current, and checks
  the example data regenerate byte for byte.

### Changed
- `drop_exact_and_near_duplicate_features` finds exact-duplicate columns ~15x faster with identical
  results (equivalence test against the previous implementation).
- MapLight strict-parity features are only built when a MapLight model will actually run.
- `--use-gpu false` skips GPU detection (no torch import).
- `--dry-run` now also runs the preflight checks and writes `dry_run_plan.{json,md}`,
  `preflight.json`, `run.log` and `events.jsonl` into the (planned) output directory.
- A dataset that raises during a run is recorded as `failed` and the run continues
  (previously the whole run aborted); `--no-continue-on-error` restores the old behaviour.

### Added
- **Applicability domain (C2).** `qsarena.applicability_domain`: the Roy-Kar-Ambure (2015)
  descriptor standardization approach and a kNN Tanimoto-distance domain with a training-only
  leave-one-out threshold. The `qsarena-applicability-domain` CLI now reports the standardization
  flag and counts it in its consensus label; `main()` accepts `argv` so it can be tested in-process.
- **Uncertainty and calibration (C5).** `qsarena.uncertainty`: split-conformal regression intervals
  (absolute or difficulty-normalised), LAC conformal prediction sets for classifiers, the
  probability-confidence reliability flag, ECE, Brier score and reliability-diagram bins.
- **Reliability study on the 22 official TDC splits (C2/C5/C9).** `python -m qsarena.reliability_study`
  fits one fixed reference model (random forest on Morgan + RDKit 2D) per dataset and writes
  `results/reliability_tdc22/`: `applicability_domain.csv`, `calibration.csv`,
  `per_molecule_predictions.csv` (with AD flags and conformal intervals per molecule),
  `feature_importance_top10.csv`, `split_hashes.csv`, reliability diagrams, a sample QMRF-style
  report and an environment manifest. Deterministic for a fixed seed.
- **Per-model interpretability (C9).** `qsarena.interpretability`: normalised native or permutation
  importances, and an explicit "no per-feature attribution" status for graph/3D models.
- **QMRF-style report export (C6).** `qsarena.qmrf`: five OECD-principle sections populated from a
  run; raises `QMRFInputError` naming every missing input instead of writing "N/A".
- **Environment manifest (C7).** `qsarena.provenance.write_environment_manifest`: key package
  versions, full installed-distribution list, git commit/dirty flag and hardware. The benchmark
  runner now writes `environment_manifest.json` next to `run_config.json` (non-fatal on failure).
- **ADMET-AI parity table (C4, tooling only).** `python -m qsarena.admet_ai_parity` builds
  `results/admet_ai_parity.csv`, one row per TDC dataset with explicit NA reasons. Against the
  canonical run the ADMET-AI-equivalent variant is valid on 2 of 22 TDC datasets and overlaps the
  captured Chemprop-RDKit leaderboard values on none, so parity remains untested until the
  team-owned Chemprop fix (C1) is re-run.
- **Independent TDC-22 multi-seed stage (C2, tooling only).** `qsarena-benchmark --tdc22-multiseed`
  now reads selected models from an existing source run, writes all seed artifacts under a new
  `--output-dir`, reuses completed per-seed `metrics.csv` files on resume, and writes the compact
  mean/SD table requested by the work order to `results/tdc22_multiseed.csv` by default. Unit tests
  cover the summary table, resume path, and independent entry point; the expensive 5-seed x 22-run
  replication itself has not been run.
- **Thin work-order guard tests (C1/C4).** Added tests that the full Chemprop configuration still
  enumerates all five variants, including the ADMET-AI-equivalent `D-MPNN + RDKit2D`, and that
  ensemble member filtering uses the train split when `member_selection_split="train"`.
- **Tests and CI.** `tests/unit` and `tests/integration` (pytest; markers `gpu`, `slow`), a
  48-molecule fixture from the official TDC splits, and `.github/workflows/ci.yml` (pytest on
  Python 3.10-3.12, ruff, and a `proof.tex` LaTeX build that fails on undefined references).
  `pip install -e .[dev]` installs the tooling.

- Ruff import-order and unused-import fixes in `qsarena/`.
